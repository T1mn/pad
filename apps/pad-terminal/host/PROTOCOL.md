# PAD native workbench v1 (implementation contract)

Transport: Swift Process stdin/stdout, UTF-8 JSONL split only on LF; stderr is diagnostics, never protocol. Maximum complete frame 8 MiB. Requests `{id, command, ...fields}`; response `{type:"response",id,command,success:true,data}` or `{...,success:false,error}`. Unique IDs, asynchronous correlation, timeouts. No request payload/credential logging. Empty data = `{}`.

## DTOs (camelCase)

- Workspace: `{id,name,path}` (absolute existing directory).
- Profile: `{id,name}`. Secrets remain exclusively in that profile's Pi agent dir.
- Task: `{id,workspaceId,profileId,title,status,provider?,modelId?,sessionFile?,updatedAt}`. Status `idle|starting|running|error`; updatedAt ISO string. Profile/workspace immutable after creation.
- Snapshot: `{workspaces:[],profiles:[],tasks:[]}`.
- Catalog: `{profileId,providers:[{id,name,authTypes:["api_key"|"oauth"],authenticated}],models:[{provider,id,name,source?,selectable?}],openaiDiscovery?:{state,updatedAt?,message?}}`. `source` is `openai_account|sdk`; omitted `selectable` defaults to true for compatibility. OpenAI discovery state is `not_loaded|fresh|stale|error`. Models only for that profile's configured/authenticated providers; no ambient host credentials or automatic catalog network refresh.
- Auth state: `{profileId,provider,method,phase,attemptId,message?,promptId?,promptKind?,placeholder?,options?:[{id,label}],url?,userCode?}`. Phase `running|succeeded|failed|cancelled`; promptKind `text|secret|manual_code|select`.

## Commands

- `snapshot` → Snapshot. Creates an empty isolated default profile if metadata does not exist, never discovers/imports existing Desktop or CLI profiles.
- `add_workspace {path}` → Workspace, deduplicated canonical path.
- `add_profile {name}` → Profile with generated safe ID.
- `create_task {workspaceId,profileId,title?}` → Task, no model prompt.
- `catalog {profileId,refreshOpenAI?:boolean}` → Catalog. Only explicit 「同步 OpenAI 模型」 supplies `refreshOpenAI:true`; normal startup/menu/task catalog reads are offline. Include only callable installed Pi SDK login methods allowed by PAD policy; exclude Claude subscription OAuth and Gemini CLI/Antigravity subscription providers, including their credentials from model availability. Retain Anthropic/Gemini API keys and other SDK-supported/configured flows.
- `history {taskId}` → `{messages:[Pi AgentMessage],truncated?:boolean}`; can start an offline RPC child to load this task's own history; never prompt. Limit to most recent 200 messages/within frame budget and disclose truncation.
- `local_sessions` → `{sessions:[{id,tool,sessionId,title,cwd,file,updatedAt}],roots:[{tool,path,status}],truncated,scannedAt}`. Explicit, read-only standard-directory discovery for Codex/Claude/Pi; `id` is an opaque path-derived key, not a client-supplied path. No credential/settings scan. Async bounded traversal, metadata cache; UI polls only while open/active.
- `local_session_history {sessionId}` → `{messages:[{id,role,text}],truncated}`. Read-only preview, no SDK `SessionManager.open` on originals (it may migrate them). Pi shows the active tree branch; Codex event/response duplicates are not shown twice. Text/tool excerpts only.
- `local_session_resume {sessionId}` → `{cwd,executable,args}`. Validate known source identity/path/cwd and resolve a standard installed CLI. No process starts in the host; only after UI confirmation may Swift create a new terminal using individually shell-quoted argv. Original CLI owns its authentication and writes; warn to stop the same session elsewhere first.
- `local_session_import_pi {sessionId,profileId}` → `{task,snapshot}`. Explicit complete snapshot (≤32 MiB, supported Pi formats), new session id/private task file, original unchanged. No copied credentials or selected model. Codex/Claude are rejected rather than converted to Pi.
- `set_model {taskId,provider,modelId}` → Task. Reject busy task; validate model belongs to profile catalog; never silently substitute provider/model.
- `prompt {taskId,message}` → `{disposition}` (Pi accepted, not completed). Reject empty input, no selected model, no credentials, or concurrent prompt. Only this explicit command initiates model work.
- `abort {taskId}` → `{}`. Clear queued messages then abort active work; retain history.
- `auth_begin {profileId,provider,method,attemptId?}` → Auth state immediately, run login asynchronously. Reject unsupported auth method and profile with active tasks. Only explicit user action calls SDK login. API key entry and OAuth both use native prompt/notice events, never CLI TUI.
- `auth_respond {profileId,promptId,value}` → `{}`. Match active prompt id/profile. Secret value stays in memory/SDK only, never state JSON, output or diagnostic logs.
- `auth_cancel {profileId,attemptId?}` → `{}`. Abort SDK operation and reject pending prompts; prevent cancelled attempt mutating current UI.
- `logout {profileId,provider}` → `{}`. Reject while profile task/auth busy. SDK logout only, never manually write auth.json.
- `shutdown` → `{}`, then close owned child processes and exit; stdin EOF/SIGTERM also shut down.

## OpenAI account discovery

OpenAI OAuth uses the official [SIWC models contract](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference/): explicit sync resolves SDK OAuth bearer privately, then `GET https://api.openai.com/v1/models` (15s bound, ≤1 MiB, no redirects). Parse `models[]`, not generic API `data[]`; keep `visibility:"list"`, preserve order, display `display_name`, identify by trimmed `slug`, deduplicate slugs. No static OpenAI OAuth fallback. API-key / other-provider catalogs remain SDK-derived.

Private per-profile `pi-agent/pad-openai-models.json` (0600, atomic publication) holds only metadata and a conservative credential-file stat binding; no bearer/JWT or inferred stable account identity. Restart reads stale; same-binding refresh failure may retain stale metadata with a safe error. Credential changes invalidate old caches; a binding change across SDK auth resolution fails with 「凭据已更新，请再次同步模型」 and no `/models` fetch/publication. Token rotation or concurrent changes may require another explicit sync. Login/logout invalidate discovery. Unknown runtime slugs are visible with `selectable:false`, rejected by `set_model`/availability checks. Catalog metadata is not an inference entitlement/success guarantee. No silent model selection or task/profile reassignment; existing login persists without migration. Reasoning-strength control is deferred/not implemented; no real authenticated endpoint validation is claimed.

## Events

- `{type:"event",event:"snapshot",data:Snapshot}` on metadata/task status changes (coalesce if necessary).
- `{type:"event",event:"pi",taskId,data:PiJsonEvent}` for raw Pi events; Native Model normalizes for UI. Pi `message_update` is delta-only. `message_end` authoritative. Use `agent_settled`, not only `agent_end`, for completion. Tools keyed by toolCallId. No stdout debug banners.
- `{type:"event",event:"auth",data:AuthState}`. Client generates attemptId before auth_begin (host generates one for older clients); ignore events/responses for a superseded attempt. Do not serialize the SDK login result (it contains tokens). On success the client refreshes catalog. SDK error details which may contain credentials must be replaced by safe app-owned classifications (otherwise a generic authentication error). Preserve authorization URL notices through manual-code prompts. If credentials committed but synchronization failed, tell users to refresh/restart, not repeat login; await idle peer cleanup before releasing auth ownership.

- `{type:"event",event:"host_warning",data:{code:"system_proxy_not_adopted"}}` at startup when macOS proxy adaptation rejects unsupported bypass/PAC or invalid system endpoints. Only this fixed code is accepted; no raw messages, environment values or proxy URLs. Native translates it into a dedicated persistent proxy warning (independent of snapshots/login errors/connection status): system routing was not adopted; configure explicit HTTP_PROXY/HTTPS_PROXY and NO_PROXY; routes without explicit proxy remain direct. Unknown codes are ignored.

## Ownership/lifecycle

Host data root: nonempty `PAD_TERMINAL_DATA_ROOT` if explicitly supplied, else `~/.pad/preview`; legacy `~/Library/Application Support/PAD Terminal Preview` alone blocks default initialization with actionable migration/root-choice instructions. Explicit `../scripts/migrate-data-root.mjs --confirm-closed` requires closed PAD/standalone clients using that root, reserves an absent destination, stages privately, marks incomplete publication, writes receipt last, retains source and rebases only owned session paths/headers. No automatic merge/overwrite; both roots require a valid unchanged-source receipt or explicit root selection. Do not run the old installation after relocation. Startup and standalone bridge leases exclude concurrent migration; unknown/stale locks require investigation. Installation UUID at `v1/installation-id.json` is lazy, stable per root and copied intact; SDK OpenAI login receives a synchronous device ID callback. Invalid identity is rejected, never silently rotated. Policy references: https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use and https://geminicli.com/docs/resources/tos-privacy/ . Other provider policies are not comprehensively audited, real login is not verified.

Metadata metadata at `v1/workbench.json`, private directory/file modes and atomic writes. Match Desktop's profile/task design, not its database or Electron dependency. Reuse `../scripts/pi-session.mjs` launchSpec for child env/dirs. Per-task Pi processes, shared starts must be de-duplicated, restore only the task's own session path inside profile sessions. Cache metadata on `get_state`; never migrate user credentials. Local history is accessed only through the explicit `local_session*` commands; Pi imports are independent copies, never bidirectional writes. Single host lock in its data root to prevent two app instances corrupting metadata. Reject unknown/corrupt state instead of overwriting it.

Host discovers installed Pi package only from explicit PAD_PI_PACKAGE or existing Homebrew/system global locations; no install/upgrade. SDK auth/catalog uses explicit per-profile auth/models paths, refreshOnCreate:false / allowModelNetwork:false. Node host itself must sanitize inherited provider credentials/NODE_OPTIONS before SDK import. Task peers use sanitized launchSpec env, offline startup, no auto-loaded extensions. Unknown extension UI requests fail closed (cancel); never silently approve permission requests.

UI selected workspace/task/profile is app-owned, task selection may not retarget an existing shell with injected `cd` or commands. Terminal stays stable across task selection. Explicit “项目终端” may create a fresh Ghostty tab with that cwd. No daemon/keepalive promise.

## Native shared model API (for parallel implementation)

`@MainActor final class PADWorkbenchModel: ObservableObject`, `static let shared`.
Published: `snapshot: PADSnapshot`, `selectedWorkspaceId:String?`, `selectedTaskId:String?`, `activeProfileId:String?`, `catalog:PADCatalog`, `messages:[PADChatItem]`, `draft:String`, `errorMessage:String?`, `proxyWarning:String?`, `connectionStatus:String`, `authState:PADAuthState?`, `historyLoading:Bool`, `catalogLoading:Bool`, `openaiRefreshing:Bool`.
Computed: `selectedWorkspace:PADWorkspace?`, `selectedTask:PADTask?`, `isBusy:Bool`, `canSend:Bool`.
Methods (UI calls synchronous wrappers that launch Tasks): `start()`, `reload()`, `addWorkspace(path:String)`, `addProfile(name:String)`, `selectWorkspace(_ id:String)`, `selectTask(_ id:String)`, `selectProfile(_ id:String)`, `createTask(title:String)`, `setModel(provider:String,modelId:String)`, `syncOpenAIModels()`, `send()`, `abort()`, `beginAuth(provider:String,method:String)`, `respondAuth(promptId:String,value:String)`, `cancelAuth()`, `logout(provider:String)`.
Selecting a task selects its immutable workspace/profile and refreshes history/catalog. The normal UI has no profile picker/creation controls: default profile owns new tasks and Pi imports; selected historical tasks use their immutable effective profile for catalog/auth/send. Extra historical profiles without tasks are retained but not normally exposed. Existing internal/protocol profile operations remain compatible; they do not mutate task ownership. Guard late history/catalog replies by selection generation. Coalesce stream publishing with a fixed ~200ms window, flush final/error/settled, and bound UI transcript length. Re-query authoritative history only on selection/settled, not every delta. Draft clears only after successful acceptance. Never auto-send on startup.

`PADWorkbenchView<TerminalContent:View>` initializer `init(openTerminal: @escaping (String)->Void, splitTerminal: @escaping (Bool)->Void = {_ in}, openSession: @escaping (PADTerminalLaunch)->Void = {_ in}, @ViewBuilder terminal: () -> TerminalContent)`. Uses shared model; owns no process. UI follows `native/DESIGN.md`: 280pt task sidebar, readable type controls and side-by-side Agent/terminal panes. Split callback: true=down, false=right, using existing Ghostty bindings. Do not conditional-destroy terminal on sidebar/task changes. Entire native Swift files guarded by `#if os(macOS)`. JSONL/business contract unchanged.

Bundled host entry: `Bundle.main.resourceURL/PADHost/host/workbench-host.mjs`; explicit `PAD_TERMINAL_HOST` developer override allowed. Node from explicit `PAD_NODE_PATH` or /opt/homebrew/bin/node or /usr/local/bin/node. Model passes minimal environment plus explicit overrides/dataRoot, not a full inherited environment. Packaging copies non-test host modules and both scripts/pi-session.mjs and scripts/migrate-data-root.mjs into PADHost. Node/Pi remain external developer prerequisites for this slice.
